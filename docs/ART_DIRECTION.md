# 游戏设计要求包括如下：

请注重游戏整体的统一性与完成度。美术、界面、图标、动画和声音应风格协调、符合内容含义。UI 要清晰易读、突出重点，文字直接简洁，减少冗余描述和不必要的操作。重要行为和状态变化要有明确、自然且适度的反馈。音乐要贴合情境、有变化、耐听，不能掩盖关键音效。游戏节奏应紧凑，尊重玩家时间，避免机械重复和人为拖长流程。请自主完成实现、实际体验验证、修复与交付。

具体为：

### 1. 整体统一性

- 画面、图标、字体、界面、动画、音效和音乐应服务于同一个主题，避免素材拼凑感。
- 表现形式要符合内容含义，让玩家看到、听到的东西与实际功能一致。
- 同一种信息和操作，应始终使用一致的名称、颜色、符号和交互方式。
- 追求完整、协调的成品感，而不只是“功能已经能运行”。

### 2. UI 与信息表达

- **突出重点，弱化次要信息。**玩家应能迅速判断当前状态、正在进行的操作和下一步选择。
- 字体足够大，关键数字、状态和提示在正常观看距离下清晰可读。
- 标题直接说明用途，避免模糊、文艺化的表达代替功能说明。
- 删除重复、冗余、装饰性过强且没有实际帮助的文字。
- 信息需要有层级，但不要把每项内容拆成过多的小标题、小标签。
- 布局充分利用空间，减少不必要的翻页和滚动，同时保持舒适的阅读密度。
- 需要做选择时，把关键差异和相关信息放在一起，方便比较。
- 用颜色和图标辅助理解，但保持含义稳定，不能只起装饰作用。
- 重要变化要及时、醒目地提示；已经结束或失效的信息应及时消失。

### 3. 美术与图标

- **可以简洁，但不能粗糙。**不一定追求复杂写实，更看重轮廓、质感、辨识度和风格一致。
- 不同来源的素材也要经过筛选和调整，不能直接混用形成明显割裂。
- 图标应贴合名称、功能或内容，让人能理解它代表什么。
- 不同含义的内容应有适当的视觉区别，避免大量复用同一个图标。
- 物体与背景之间要容易区分，避免靠生硬的描边或额外标记勉强解决。
- 偏好轮廓独立、背景透明、有一定细节与质感的图标，而非简陋的几何符号。
- 场景或状态发生变化时，整体视觉表现也应有所呼应。

### 4. 动画与操作反馈

- **玩家的重要操作都应得到明确回应。**让人知道操作是否成功、产生了什么影响。
- 动画、声音和视觉变化应与事件的重要程度相匹配，关键操作更有存在感。
- 反馈要有力度，但不能刺眼、遮挡信息或造成视觉混乱。
- 不同状态和结果应有可区分的表现，避免所有效果看起来都一样。
- 动态表现应有自然的开始、变化和结束，减少僵硬的贴图感和突然切换。
- 过渡动画应帮助玩家理解过程，不能只是增加等待时间。

### 5. 音乐与音效

- 音乐应符合游戏主题、当前情境和情绪，不是单纯找“好听的曲子”。
- 偏好有氛围、耐听的音乐，避免过于诡异、刺耳、嘈杂或情绪不合适的风格。
- 音乐要有足够变化，减少重复听腻；重要情境变化时可以相应切换。
- 背景音乐与操作音效层次清楚，音乐不能掩盖关键反馈。
- 重要操作、状态变化和结果应有贴合含义的音效。
- 提供实用的声音设置，让玩家能够调整到舒适的比例。

### 6. 节奏与体验

- **尊重玩家时间。**节奏要较为紧凑。简单、重复或已经理解的内容，不应占用过长时间。
- 尽早展示游戏真正有趣的部分，不用冗长流程延迟体验。
- 内容变化要有实际意义，避免只有外观或数值发生变化。
- 难度和复杂度应逐步展开，既不能长期平淡，也不能突然制造不合理压力。
- 挑战应来自理解、判断、操作或策略，避免依靠漫长等待和机械重复延长过程。
- 玩家投入时间后，应持续得到新的体验、明确进展或有价值的选择。

### 7. 易用性与完成度

- 常用操作应方便、直观、响应及时，减少没有必要的步骤。
- 默认设置应适合直接开始体验，同时保留必要的调整选项。
- 自动处理没有决策价值的重复事务，但要让玩家看得懂处理结果。
- 提示和指南应在需要时提供帮助，而不是堆积说明文字。
- 需要保存进度的游戏，应可靠保存、方便恢复，并尽量兼容后续更新。
- 不同入口、界面和流程都要保持同样的完成度，不能只打磨主要画面。

### 8. 开发与交付方式

- 请你完整的完成整个实现流程，不要让我批准任何内容，请自主进行开发、测试。
- 如果未达到完成标准，请继续分析问题并迭代，不要仅因完成一轮工作就停止。
- 开发完成后，推到github仓库中。并使用GitHub Pages部署。能够在线访问。
