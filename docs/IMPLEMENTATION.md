# 实现与验收说明

实现基线为 `GAME_DESIGN.md` 1.1 版及 `ART_DIRECTION.md`。收集品详情见 `COLLECTIBLES.md`，枪械数值见 `WEAPONS.md`。

## 技术选择

采用 TypeScript、Phaser 3、Three.js 和 Vite。地图一使用 Three.js 正交投影、立体猫咪与独立手持枪械模型；后续地图保持原有 Canvas 绘制器。角色运动、弹道、碰撞、搜索与 AI 共用局内模拟。

全部 104 件物品共用彩色 PNG 图集，采用简洁色块、深色描边和猫化外形。60 件收集品分别生成对应图标，使用测量的透明边界裁切显示，原图保持不变；运行时不依赖外部图片服务。声音通过 Web Audio 合成，本地字体覆盖全部新文案。

## 物品和进度

主线首领顺序为铁腮、闪尾、猫伊德，再到最终地图的零号缅因与霜瞳（顺序自由），最后博士。权限密钥和击败记录在成功撤离后永久保存，不占库存格。

死亡与中断遵守模式；退出本局则恢复出击前快照。结算以 pending 标志保证只执行一次。背包物品保留，玩家自行入库；武器弹匣保留在对应武器上，不生成待整理战利品。旧编号和历史溢出物资继续迁移。

主副武器直接互换或移入空栏时，物品编号、耐久、弹匣和弹种保持对应。左侧装备固定在顶部，背包单独滚动，拖拽靠近滚动区边缘自动滚动；安全箱固定在底部一行。仓库每次打开按类型、同类按价值降序展示。撤离物资价值按最终背包、安全箱中物品的实际出售总值计算，不是本局累计拾取价值。

## 自动验证

单元测试覆盖内容编号与独立描述、品质分配、主副交换和空位移动、弹种与弹匣守恒、价值结算，以及题目生成、穿甲、弹药堆叠、购买升级、武器护具修复、死亡中断、真实弹道、多弹丸霰弹、敌人协作、进食和撤离。

浏览器测试覆盖发现后图鉴点击、60 件 PNG 加载、两种分辨率的固定装备与安全箱、背包底部拖枪、主副互换、仓库默认排序、撤离鼓励按钮，以及完整搜索撤离、键鼠射击、Chrome 菜单与失焦、商店、存档和手持模型。

生产构建另验证 GitHub Pages 子路径加载、没有开发测试接口、主副拖拽、默认排序、离线加载全部收藏图标、菜单可点击和没有脚本或资源错误。部署工作流在发布后以 Google Chrome 访问实际公开地址，核对提交版本。

## 持续验证目标

约四小时首轮通关、长期经济与枪械平衡、不同硬件下的帧率仍需人类试玩统计。自动化通关状态准备仅用于验证结算和界面。
