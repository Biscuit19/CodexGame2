# 实现与验收说明

实现基线为 `GAME_DESIGN.md` 1.3 版及 `ART_DIRECTION.md`。收集品详情见 `COLLECTIBLES.md`，枪械数值见 `WEAPONS.md`。

## 技术选择

采用 TypeScript、Phaser 3、Three.js 和 Vite。地图一使用 Three.js 正交投影、立体猫咪与独立手持枪械模型；后续地图保持原有 Canvas 绘制器。角色运动、弹道、碰撞、搜索与 AI 共用局内模拟。

全部 119 件物品共用彩色 PNG 图集，采用简洁色块、深色描边和猫化外形。70 件收集品分别生成对应图标，使用测量的透明边界裁切显示，原图保持不变；运行时不依赖外部图片服务。声音通过 Web Audio 合成，本地字体覆盖全部新文案。

## 物品和进度

主线首领顺序为铁腮、闪尾、猫伊德，再到最终地图的零号缅因与霜瞳（顺序自由），最后博士。权限密钥和击败记录在成功撤离后永久保存，不占库存格。

死亡与中断遵守模式；退出本局则恢复出击前快照。结算以 pending 标志保证只执行一次。背包物品保留，玩家自行入库；武器弹匣保留在对应武器上，不生成待整理战利品。旧编号和历史溢出物资继续迁移。

主副武器直接互换或移入空栏时，物品编号、耐久、弹匣和弹种保持对应。左侧装备固定在顶部，背包单独滚动，拖拽靠近滚动区边缘自动滚动；安全箱固定在底部一行。仓库每次打开按类型、同类按价值降序展示。撤离物资价值按最终背包、安全箱中物品的实际出售总值计算，不是本局累计拾取价值。

## 持续验证目标

约四小时首轮通关、长期经济与枪械平衡、不同硬件下的帧率仍需人类试玩统计。自动化通关状态准备仅用于验证结算和界面。

新增持续回血状态仅存在于本局模拟；暂停停止推进，不进入永久存档。可选 discovered 字段现仅登记收藏品首次搜索，collection 仅保留收藏品；旧版本遗留的非收藏发现记录不再触发提示。旧版五件食品收藏记录迁移到 discovered，实物保留，图鉴移除。搜索揭示立即登记与持久化，不依赖拾取容量。

## Chrome和本轮交互验收

图鉴详情复用菜单的原生顶层dialog模式，直接挂body，无嵌套fixed遮罩或backdrop-filter。真实Google Chrome检查各品质详情、关闭按钮、Esc、顶层命中和高层画布覆盖情况，并截屏确认实际绘制。CI对全部浏览器用例同时执行Chromium与Chrome，不再仅抽样菜单。

仅收藏品首次发现使用独立固定顶部提示层和品质优先队列，删除旧右下角高品质重复通知，五档停留1／1.5／4／5.5／7秒。提示不随背包重绘丢失；珍贵以上包含标题、原描述与彩色物品名，低品质仅名字。武器与弹药图标按当前装备ID与弹种缓存更新，不逐帧替换图片节点。

补给与弹药共用堆叠事务，限额分别5和90。容量检查先于合并，失败不得部分移动；旧单件食物自动合并。食用、出售、回购与结算均按实际份数处理。

临时测试用Save.temporary标记，persist在任何写入前返回；界面也不更新正式槽缓存或activeSlot，不显示导入导出。退出本局保留临时标记，临时战斗结算不落盘。Chrome测试对四张地图、购买、设置、退出、结算与刷新前后的localStorage和IndexedDB正式记录进行完整比较。

战斗右下角采用横向枪械／弹药双栏，不给武器图片添加单独背景。滚轮按方向循环主枪、副枪和近战，跳过未装备位，复用 selectWeapon 保存各枪弹匣。商店食物按价格、武器按品质及价格升序。图鉴仅已发现按钮附带 data-item，复用悬浮描述组件。

带出价值由 Raid.extractedLootValue 统计本局新带回物资，覆盖背包、安全箱、穿戴栏和枪内剩余新弹药。Item.raidBrought 与 loaded.raidBrought 记录带入份数，堆叠转移保留来源；消耗优先扣该堆或弹匣中的带入部分。结算清除标记，下一局重新标记所有带入物资，不修改原有售价或实际金币。主动退出仍回滚原快照。基地子页面 Esc 返回基地，详情和菜单弹窗先关闭，结算保留至点击返回。

新增Equipment.food（旧存档迁移默认null），整堆食物不占背包格。出击前快照先于自动食物装备，主动退出准确回滚。Raid.ensureFood按品质、价格选择并转移原Item引用，保留raidBrought来源；成功食用扣一份，耗尽后清除当前栏并续装。背包和装备食物都可按uid直接食用，容器进食不转移物品。结算、死亡回购和价值统计包含食物装备位。

16件收藏图标由图像工具生成，保留原始PNG，不做图像编辑；household-frames.ts按透明像素组件测量边界，优先于旧图集映射。旧餐盒编号变food，validateSave从collection剔除、保留discovered与实物。替换收藏沿用旧ID；新增c6_0维持70件。解锁提示使用名字＋图标首行、描述末行，优先级覆盖时丢弃当前消息，避免旧提示再次出现。

## 矮胖猫咪与方向翻滚

地图一 ThreeRenderer 保持正交投影，将猫咪整体缩至原来的78%，缩短身躯和四肢、增大圆脸比例，眼睛用独立节点缩放完成眨眼。六节尾巴以错开的相位摆动，敌我分别错开眨眼与尾巴相位。头盔位于两耳之间，胸甲采用小型胸片和肩带，按实际装备品质着色；空装备或敌甲破损时隐藏。

身体旋转中心移动到腹部，翻滚使用移动方向垂直的水平轴四元数旋转，保持朝向独立，因此向前移动表现为前滚翻、反向移动表现为后滚翻。仅成功开火、近战攻击和翻滚取消进食，装填、换枪、移动、受击不会取消。弹药上限120发，敌猫按战局随机数生成20～50发备弹。所有普通通知集中顶部中央，发现提示出现时自动让出其下方空间。

## 八方向滚翻与弹药事务

停止疾跑立即按每秒24点恢复体力，翻滚期间不叠加步行移动和疾跑消耗。翻滚保存起始瞄准方向，按移动方向转向后只绕猫咪腹部的横轴前后滚翻，因此八方向均使用同一滚翻动作。

selectAmmo在克隆数据上完成备弹切换、旧弹匣退回、装填和补满120发，再检查最终背包容量后提交；失败不会部分交换。refillAmmo保留每份弹药raidBrought来源，应用于迁移、初始装备、拾取、入包与重新装填；弹药装备位的品质与拖到武器的弹药同步。安全箱升级复用挂在body上的base-menu原生dialog，去掉旧fixed遮罩，Chrome验证包含截图、点击命中、购买、关闭和Esc。CI为软件渲染测试预留60秒，并为每套浏览器启动独立开发服务器。

## 玩家 C 方案三花模型

地图一玩家改用独立的 `player-cat.ts`，敌猫继续使用原模型。头与双耳由连续隐式曲面生成并保留平滑梯度法线；三花色块、眼睛、鼻口、短胡须和内耳均在表面绘制，避免附着球体五官。整体为短腿、圆身、短手的双足三花猫，不显示围巾，保留小布兜。玩家头盔、胸甲、背包不创建可见几何体，但装备、护甲效果与库存数据照常保留；手持枪与近战武器继续显示。

待机包含呼吸、目光轻移、分时眨眼、独立耳朵微动和偶发抖耳。尾巴为一条连续蒙皮曲面，六根骨骼错相摆动，不再以分离球节构成。双足跑动由左右脚交替、对侧手臂前后摆动、轻微身体扭动和头部点动共同完成；持枪手摆幅略小，武器随手移动。八方向翻滚继续复用原有移动方向与瞄准方向判定。

真实 Google Chrome 验证玩家与敌猫模型区分、装备数据保留且外观隐藏、眨眼与耳尾待机变化、双手双脚相反相位、持枪、八方向滚翻；留存原始游戏视角、放大正面／侧面／背面截图与实际跑动录像。模型材质着色器的编译错误纳入浏览器测试失败条件。

## 圆团玩家与两秒足迹

玩家沿用已确定的三花身份，改为 B 圆团比例并稍多露出身体：宽圆脸、压短的圆肚子、更饱满的圆角三角耳和缩小的脚掌。额头色块从顶部中央分开，向两侧下方展开，白色脸部在下方变宽；手脚均为白色，表面绘制两条细爪趾线。保留布兜、手持武器和独立四肢／头部动作，敌猫外观与装备数据不变。

地图一脚印属于本局临时视觉状态，不进入存档。正常移动累计约 52 个世界单位才留下一个左右交替的猫爪印；按实际位移计数，顶墙不生成，翻滚不生成且重置步距。每个脚印在两秒模拟时间内逐渐淡出，暂停时冻结；新一局从空足迹开始。Three.js 使用同一张自绘爪印纹理、共享几何体与固定 16 格网格池，不逐帧创建贴图或模型。单元测试覆盖间距、左右交替、暂停、两秒消失、顶墙和翻滚；真实 Chrome 检查游戏内正背面、跑动、足迹可见及淡出。

## 33 度斜视与搜索受击

地图一正交相机的俯视角从 45 度降低到 33 度，继续使用同一射线平面进行鼠标反投影，弹道坐标不另加人工偏移。每段墙的墙身、顶盖和竖条合并为同一个顶点色网格；按新相机角度判断前景遮挡并一起淡化，离开后恢复，避免不透明的墙顶残留遮住玩家。

玩家耳根加宽并向头顶内移，耳动幅度增大。尾根通常大幅左右扫动，尾尖延迟跟随，周期中短暂减小幅度。眼睛、鼻嘴上移并放大，胡须加粗、加长并扩展到侧脸。脚掌进一步压短，三条爪趾线绕过脚尖延伸到脚底，抬脚时仍能看到。保留原有白色手脚、布兜、持枪、跑步足迹和方向滚翻。

非致命受击保留容器搜索对象、界面和逐件揭示进度；致命伤害仍按死亡结算关闭本局。主动移动、翻滚、退出搜索等原有操作继续生效。测试包含实际敌方弹丸命中后搜索不中断、完整揭示并拾取，以及相机角度、投影反投影一致性和墙体整体淡化／恢复。

低帧率眨眼按有限帧步长推进，并在跨过闭眼时刻时保留一帧完整闭眼，避免慢帧跳过整段动画。浏览器测试逐个渲染帧记录最小睁眼值，不再通过远程轮询碰运气采样短暂姿态；单元测试覆盖正常帧率、每秒两帧和不规则长帧。


## 相对瞄准方向的步态与翻滚

地图一玩家以瞄准朝向为零度，顺时针计算实际位移：−45°～45°（含边界）前进，135°～225°（含边界）后退，其余为左右侧移。`src/locomotion.ts` 统一处理角度归一、方向分类和滚动轴。碰撞后的真实位移方向传给动画；顶墙不再原地播放踏步。

前进保持交替迈爪与反向摆臂，后退缩短步幅并反转脚步、摆臂、重心及点头方向；侧移让爪子主要横向交替挪动，搭配侧向摆臂、身体重心与头部平衡。脚掌在回收阶段抬起，停步恢复默认位置。

翻滚保持开始时的瞄准朝向，以垂直于实际移动的地面轴转动：前后为前后翻，左右为侧翻，斜向混合两轴，绝不绕竖轴自转。尾巴、耳朵、眨眼与脚印仍沿用原有逻辑。敌人造型和后续地图的旧版绘制不改。

本次按范围选测：相对方向边界与翻滚数学测试、实际键盘四向步态和八向翻滚浏览器用例，以及移动/脚印相关回归。未执行全量回归。


## 矮身玩家与贴合装备

地图一玩家躯干由半径20×15×14.5缩为16×9.5×11.5，头部中心降低8单位。正面头下可见躯干由约17.5缩为约8.5单位；头宽收窄，耳根从±16.8移到±14.8，眼、鼻嘴、胡须整体上移1.5单位。短手放大10%，手持武器由0.68放大到0.98，并调整握持位置。移动中的身体晃动、头部点动、摆臂、迈爪和抬脚幅度均增加，保留前进、后退、左右侧移的区别。

尾巴六段骨骼采用不同频率、相位与延迟的平滑组合波，根部大范围扫动，尾尖额外左右摆动、上挑与卷动。每只猫有随机初始相位，不使用逐帧随机抖动。

恢复玩家装备外形：头盔取同一头部表面的上部形成贴合猫耳壳，与毛皮共享耳部变形公式和uniform；切边精确裁到水平面，避免锯齿。短护甲覆盖上躯干，露出下腹，手臂不包甲。背后小包随五档容量等级从0.7增大到1.0。五级头甲与背包通过颜色区分；换装只更新可见性、颜色和背包缩放，不重建几何，也不改变装备数值。敌人和后续地图仍保持原模型。

针对性验证：五项眨眼/尾巴动画单元测试，玩家连续模型与放大步态、实际四向移动、五级装备穿脱及前后视图浏览器检查。未运行无关全量回归。


## 完整尾巴扫动与五款原画头盔

修正尾巴静态曲线向左偏的问题，改成居中的上翘曲线并降低尾根。尾根约±75°扫动，中段轻微延迟，后段通过侧弯带动实际尾尖；检查骨骼世界位置与最后一段的切向，而不再只看末端关节角度。实际根段、尾中、尾尖位置与尾尖朝向均跨越左右中线，仍使用平滑的多频率变化。

新增 `src/player-helmets.ts`：五款独立模型按装备PNG原画配色与结构绘制。旧钢盔为银灰钢壳、卷边、铆钉和挂带；猫耳战术盔为橄榄绿、正面方块挂架与独立侧板；防弹头盔为蓝壳、浅青护目镜与耳罩；特勤面罩盔为紫壳、紫色镜片、鼻梁护板及呼吸格栅；九命全覆盔为象牙白壳、金色边框、黑色T形面罩与分块颊甲。细节几何烘焙在头部坐标中，与猫耳共用变形，穿脱只切换模型可见性。

手持武器相对上一版缩小15%，局部比例由0.98变为0.833。人物世界移动速度上下左右相同；33°正交俯视使纵向在屏幕上缩为约sin(33°)，因此横向看起来约快1.84倍。此次不改变移动规则。

本次选测尾巴两项单元测试、五款头盔穿脱/细节/原画配色/耳壳联动与尾巴实际左右跨度的一项浏览器用例，并检查背面扫动截图及生产构建。未运行全量回归。


## 随机全向尾尖与头部避让

尾巴独立到 `src/player-tail.ts`。尾根保留大幅左右扫动，并加入轻微前后倾动；尾尖每2.6秒按个体随机种子选取完整360°范围中的新方向，以五次平滑插值沿最短转向过渡，跨过0°时也不会突然跳转。中段以连续样条跟随，尾尖朝向由末段曲线本身形成。

改为复用60环连续管面的顶点、法线缓冲：每帧更新曲线与平行传递的截面，不再只转动末端骨骼。按当前头部位置和旋转，将曲线采样转换到头部局部空间，使用含尾巴半径与安全余量的保守包围体向后避让，之后再生成表面。管面截面的顶点顺序保留TubeGeometry索引的朝向，避免绘制成内侧；浏览器检查三角形几何法线与表面法线一致。翻滚收头姿势也在避让之前更新。
